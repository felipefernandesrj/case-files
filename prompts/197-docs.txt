Facts (write them in your own full sentences): A backer asked how much one game can cost. Each playthrough (one game session) now has a cap on model calls. A case can set its own cap with a whole number field maxCalls from 1 to 100; without it the default is 20 (DEFAULT_MAX_CALLS in the new file src/budget.js). Every question that reaches the model counts, even if the model call fails, because a failed call may still cost. Once the cap is reached, the server answers 429 with error call_cap and a friendly message in English or Portuguese, makes no model call, and the player can still accuse or start a new game, which gets a fresh cap. The English message is: You have used all the questions for this case in this game. Make your accusation, or press Start over for a new game. The new function worstCaseSpend computes the worst-case cost of one playthrough: every call is assumed to use the full max_tokens of 300 and to resend the longest system prompt plus the whole history so far, counting one token per character, at the published price of the play model llama-4-scout (US$0.27 per million input tokens and US$0.85 per million output tokens). The documented ceiling is US$0.10 per playthrough (PLAYTHROUGH_CEILING_USD). Today the worst case is about US$0.061 for The Vanishing Violin and US$0.060 for The Night Train. A new test file test/budget.mjs has 8 checks, so the suite has 127 checks in total (was 119). A short live question in Portuguese through the Cup key still got a normal answer under the cap.
